# Banco no Supabase (Postgres)

A plataforma funciona com dois bancos, com o mesmo código:

| Sem `DATABASE_URL` no `.env` | Com `DATABASE_URL` no `.env` |
|---|---|
| SQLite em `dados/concilia.db` (não precisa instalar nada) | Postgres, por exemplo o do Supabase |

As tabelas são criadas sozinhas na primeira vez que a plataforma abre. O SQL do sistema é escrito uma vez só e traduzido para o Postgres em `app/db.py`.

## Como ligar

1. No Supabase, abra o projeto **Concilia AI SP** (região São Paulo, `sa-east-1`).
2. Clique em **Connect** → **Direct** → **Session pooler** e copie o endereço (`postgresql://postgres.<projeto>:[YOUR-PASSWORD]@aws-1-sa-east-1.pooler.supabase.com:5432/postgres`).
3. No `.env` da pasta do projeto, coloque uma linha só:
   ```ini
   DATABASE_URL=postgresql://postgres.<projeto>:SUA-SENHA@aws-1-sa-east-1.pooler.supabase.com:5432/postgres
   ```
   A senha pode ter símbolos (`@ # / ? :`): o sistema codifica sozinho. Se esqueceu a senha: **Database → Settings → Reset database password**.
4. Abra a plataforma (`iniciar.bat` ou `uvicorn app.main:app --port 8000`).

Use o **Session pooler** (porta 5432): ele funciona em redes só IPv4 e mantém a sessão, que o sistema usa para escolher o esquema. Não compartilhe a senha em chat, commit ou print.

## Onde ficam as tabelas

No esquema **`concilia`** (mude com `CONCILIA_PG_ESQUEMA`), e não no `public`. O Supabase publica o esquema `public` pela API REST do projeto para quem tem a chave pública; o `concilia` não é publicado, então os dados só saem pela API da Concilia. No painel: **Table Editor → schema: concilia**.

O projeto foi criado com "Automatically expose new tables" desligado e RLS automático ligado, como reforço.

## O que muda entre os dois bancos

| Recurso | SQLite | Postgres |
|---|---|---|
| Busca no texto | FTS5, sem acento | `tsvector` com `unaccent`, índice GIN |
| Auditoria do ERP imutável | gatilhos `RAISE(ABORT)` | gatilhos em PL/pgSQL |
| Ids gerados | `INTEGER PRIMARY KEY` | `GENERATED BY DEFAULT AS IDENTITY` |
| `INSERT OR IGNORE` | nativo | `ON CONFLICT DO NOTHING` |

## Testes

Os testes **nunca** usam o banco do `.env`: rodam num SQLite temporário. Para rodar no Postgres:

```bash
CONCILIA_TESTE_POSTGRES=env .venv/Scripts/python.exe -m pytest -q tests     # usa a DATABASE_URL do .env
```

Eles criam um esquema temporário (`teste_xxxx`) e o apagam no fim, sem tocar no esquema `concilia`.

## Limites desta versão

- Uma conexão por processo, com as consultas em fila: suficiente para a demonstração; em produção, trocar por um pool de conexões.
- Cada consulta paga a ida e volta até o Supabase (na medição daqui, cerca de 230 ms): telas com muitas consultas ficam mais lentas que no SQLite.
- As imagens das páginas, miniaturas e PDFs continuam no disco do servidor (`dados/`). O próximo passo é levá-los para o Storage do Supabase.
